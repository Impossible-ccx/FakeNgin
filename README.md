# FakeNgin

基于本地模型的消息风险分析平台。`main-rebuild` 从 main 的 `86c7a50` 开始，按功能拆分改进，方便维护者选择提交。当前模型登记及搜索算法与 main 的 `f4b7495` 对齐，历史和批量任务使用文件存储。

## 安装与运行

安装 Python 3.10–3.14，下载或克隆仓库。Windows 双击仓库中的 `run.bat`；macOS、Linux 或希望使用命令行时运行：

```bash
python scripts/start_web.py
```

启动器根据脚本位置定位仓库，支持中文、空格路径和从其他目录启动。现有 Python 环境已包含依赖时直接复用；否则在仓库内建立 `.venv` 并安装基础依赖，首次安装需要网络。基础依赖包括本地模型服务的 Python 客户端，不安装 torch、模型服务程序或模型权重。启动后自动打开浏览器，无需安装数据库服务。

不打开浏览器、检查当前环境或指定端口：

```bash
python scripts/start_web.py --no-browser
python scripts/start_web.py --check
python scripts/start_web.py --port 5001
```

默认网站位于 http://127.0.0.1:5000/ ，风险检测位于 http://127.0.0.1:5000/detect 。启动器关闭调试和自动重载，以单个网站进程运行。也可自行安装 `requirements.txt` 后运行 `python src/app.py`。
没有模型也可以打开页面。检测页只展示实际可用的风险模型；一个模型时默认单模型，至少两个时才启用投票。数据页仅读取缓存状态，不连接模型服务；点击“检查模型连接”可刷新名单，启动模型服务后无需重启网站。检测页再次打开时也会按短期缓存更新可用状态。网站不会自动下载模型。

模型名单查询只检查可用性，不初始化模型权重。真正检测时才初始化所选模型，并发首次调用共用同一实例；连接或初始化失败后可重试，不会一直锁定为不可用。风险页面只探测风险模型，不探测或初始化 RoBERTa 分类器。本地服务安装名单共用 5 秒缓存，连接检查使用 2 秒超时；实际推理仍使用各模型原有超时。

网页、数据导入、搜索、历史查看和人工校验均可在没有模型的电脑上运行。真实检测需启动本机已配置的模型服务并准备对应模型。网站不会自动下载权重，也不需要别人的 API 密钥。

原有数据管理页面的本地测试账户为 `admin` / `admin`。风险检测无需登录，也不写入人工审核队列或真假标签。

## 页面入口

首页和主导航使用四个模块：数据展示 `/data`、检测结果 `/detect`、人工校验 `/verify`、关键字搜索 `/search`。检测结果模块内可进入历史报告 `/history`；数据和搜索中的最近报告也直接连接对应历史详情。

布局采用紧凑的分区标题、消息卡片、可展开原文和状态配色，小屏幕下数据表按消息堆叠展示。模型在网页上按登记顺序使用“分析模型 N”名称，暂时离线不会改变其他模型的编号；原始模型标识仍保存在完整报告中。没有云端 API 配置入口，服务启动不会下载模型。

## 人工校验

`/verify` 登录后可添加、编辑、删除、标注、跳过或恢复消息。待校验队列位于页面顶部，支持按全部／待校验／已校验筛选，也可通过文件、行号和内容指纹定位消息。跳过状态按浏览器保存，相同正文的不同数据行可以独立跳过。

提交时检查正文长度、标签、来源、有限分类分数和原行指纹，拒绝过期或伪造的位置。人工标签与机器风险字段分开保存；编辑正文会清除该行过时的风险字段。页面支持无 JavaScript 的编辑和删除确认。

## 风险投票

网页沿用 main 的 `checkmodel.MODEL_MODULES` 作为唯一模型登记入口，从中动态筛选 `score_kind="risk"` 的模型，不再另设三个固定型号的白名单。新增适配器后只需在该列表登记，不需要修改投票或网页代码。候选模型可超过三个；每次投票仍按原规则选择两个或三个，页面默认最多选择三个。风险名单查询不会改写全局模型配置。未知模型 ID 在推理前被拒绝，已登记但临时不可用的成员仍按不可用处理。每个实际调用的适配器必须提供 `score_kind="risk"`，真假分类概率不会参与风险投票。各模型使用相同的风险定义，独立分析来源描述、证据表述、绝对化断言、恐慌煽动、强迫转发等文本特征。通知、科普、引用专家或情绪表达本身不构成高风险依据。

风险分为 0–100 分，不是真假概率。高风险不等于虚假，低风险也不保证真实。输入缺少上下文时，模型可以返回 `risk_score: null` 表示无法评分；这与请求失败分别展示。

初始等级界线（尚未经过数据集校准）：

| 风险分          | 等级   |
| --------------- | ------ |
| 0 ≤ 分数 < 40   | 低风险 |
| 40 ≤ 分数 < 70  | 中风险 |
| 70 ≤ 分数 ≤ 100 | 高风险 |

- **单模型**：选择一个模型，显示它的风险分、等级、理由和耗时。
- **投票**：选择两个或三个模型，每个模型一票，按风险等级等权计票。不做模型相似性加权。
- 多数门槛为 `floor(选定模型数 / 2) + 1`：两模型必须同意，三模型中至少两票同等级。
- 失败、缺失与弃权不会降低多数门槛。没有多数票或有效票不足时，改用成功返回的风险分的**算术平均值**，再按同样的 40、70 界线分档。分类使用未四舍五入的均值。
- 页面明确标记“多数投票”或“平均分兜底”。如果只有一个模型成功，均值就是该模型分数，并提示仅有一个有效结果；只有零个有效分数时才无法判断。
- 失败、缺失、弃权均不计入平均分，也不按 0 分计算。均值是风险评分，不是真假概率。
- 页面展示选定数、有效结果数、各等级票数及全部成员状态；“2/3 支持”只是投票比例。
- RoBERTa 学习真假标签，不参与本次风险投票；固定 50 分的模板模型默认禁用，其分类概率也不参与风险投票。

示例：80/90/10 → 高风险（多数票 2/3，优先于均值）；10/50/90 → 中风险（均值 50）；90/10 → 中风险（均值 50）；90/失败/弃权 → 高风险（均值 90，只有 1/3 有效）；全部失败或弃权 → 无法判断。

本地模型顺序执行，避免同时加载多个大模型。网页根据真实事件展示每个模型的等待、分析、完成、失败或无法评分状态；完成一个就更新其评分和理由，全部执行后保存一份报告。同步表单和流式请求使用同一套聚合规则。关闭检测连接后不会再调用后续模型，也不保存未完成的报告；正在进行的本地调用需要等待返回。多模型用时取决于设备、模型加载及重试，每个模型有独立超时和最多两次请求尝试，主动弃权不重试。

提示词版本为 `risk-v1`，Ollama 返回 `risk_score` / `reason` 的 JSON Schema；客户端拒绝 NaN、越界、旧 `probability` 字段和无有效理由的响应。Qwen/GLM 使用 temperature=0；DeepSeek 保留其推荐的 0.6 和仅 user 消息的调用方式。

## 批量评分与旧数据

```bash
python src/newscheck.py
```

批处理根据 `model.score_kind` 分开存储：

- 风险模型 → `risk_score`、`risk_model`、`risk_reason`、`risk_prompt_version`。
- 原有真假分类器 → `fake_probability`。

旧 CSV 读取时为新字段补空值，写回时增加列；原来的分数和标签不会自动转换为风险分。修改来源等元信息时保留已有风险字段，修改正文时清除旧风险结果以便重新评分。数据展示页将风险分与历史分类分数分列显示。

完整的网页检测自动保存原文和模型结果；输入错误不保存，全部模型失败的完整报告也会保留。CLI 仍是单模型批处理，每 20 个成功结果保存一次，单条失败继续；强制中止时最近未保存的结果可能需要重跑。

网页 `/data` 支持粘贴每行一条的消息，或导入 UTF-8 CSV（`content`／`内容`／`正文`列）。每次最多 500 条、文件或文本不超过 1 MiB，每条正文最多 6000 字。导入只添加数据，不自动检测；校验失败不会部分写入。

勾选消息后可以启动后台批量检测，每批最多 100 条、本地模型依次运行。每条完成就保存报告并更新进度，单条失败继续处理后续消息。取消在当前模型返回后停止，已完成报告保留。刷新可继续查看进度；服务重启后未完成任务标为中断，不自动重新推理。任务保存在 `database/risk_batches/<任务ID>.json`。旧云端任务会标记中断，网站不提供云端 API 或填写密钥的入口。

数据展示和关键字搜索都能查看同一条消息的最近批量报告；关联通过文件、行号及原文指纹验证，修改正文或行号变化后不会错误复用旧报告。数据集负责消息导入、选择和人工标签，历史记录负责保存每次检测的原文快照、评分、理由和导出，两者分开存储。

## 检测历史与导出

检测页中的“已保存的检测结果”进入 `/history`，按时间浏览和搜索报告。`/history/<id>` 读取保存时的原文、评分、理由、状态与聚合结果，不重新调用模型。报告支持复制和 TXT／JSON／CSV 导出；CSV 会处理潜在公式文本。

报告独立保存在 `database/risk_reports/<报告ID>.json`，不会改写数据集原文、真假标签或 CSV 风险字段。消息与最近报告的关联保存在 `database/dataset_reports/`。重启后仍能查看，这些本地文件不会提交到 Git。保存失败时保留当前结果并显示提示。

历史、任务和关联均使用 JSON 文件；正常运行无需创建或连接 SQLite。写入使用独立临时文件原子替换，并对读改写加锁；读取按文件版本缓存，外部修改后自动失效。

网页批量任务由单个网站进程的后台线程执行，按当前启动方式运行。多个网站进程共用同一任务目录时，需要另行配置独立任务 worker；文件锁用于保护文件写入和任务领取，不负责多进程 worker 生命周期。

如果已使用本分支此前的 SQLite 版本，先停止网站，再在仓库根目录运行：

```bash
python scripts/migrate_risk_storage.py --dry-run
python scripts/migrate_risk_storage.py
```

第一条只显示待迁移数量；第二条迁移历史、任务和消息关联，保持原报告 ID、详情及导出链接。旧数据库只读并保留作备份，已有 JSON 不覆盖，可重复运行。旧的未完成任务标为中断，已完成结果保留，不重新调用模型。另存的数据目录可使用 `--database-dir <目录>`。

## 可选的 RoBERTa 训练

RoBERTa 保留为独立的真假分类实验，未参与风险页面。

```bash
pip install torch transformers
python src/train_rumor_model.py
```

训练数据为 `database/newsdata/output/` 下 CSV；权重输出到 `models/rumor-roberta/`。首次运行下载基座模型，脚本默认通过 `hf-mirror.com`，可使用 `HF_ENDPOINT` 覆盖。仓库不包含训练权重或真实模型评测结论。

## 独立关键字搜索

`/search` 沿用 main 的正文 BM25 检索：保持相同的 jieba 搜索分词、大小写处理、IDF、长度归一化、参数和排序规则。页面每页展示 20 条，支持安全高亮和定位原始数据行。来源作为结果的元信息展示，不加入正文索引。旧 `/data?q=...` 地址转到独立搜索页。搜索不会调用模型，也不修改人工标签。

派生索引继续保存在 `database/searchindex/` 的 CSV 文件中，进程内缓存倒排表及查询排序。重复搜索不再重新读取索引 CSV 或遍历全文；正文变化只重建有变化文件的索引，单独修改来源或人工标签只更新显示，不重新分词。清空内存缓存或重启后可以复用磁盘索引。缓存、分页和异常恢复仅改善执行流程，不增加新的搜索评分算法。

数据浏览、人工校验和搜索共用消息 CSV 读取与聚合缓存。文件列表、修改时间、大小及文件身份变化会使缓存失效，导入、新增、编辑、删除及外部替换都会更新数据；缓存返回副本，页面操作不会污染缓存。

已移除新增的词频云、手写停用词、前 500 条采样和“原文匹配”模式。关键字搜索模块直接复用主干检索逻辑；进入人工校验的链接仍可精确定位同一条消息。

## 测试

```bash
python -m unittest discover -s tests -v
```

测试使用模拟模型和隔离的临时数据，覆盖多数票、分歧、失败、弃权、边界、非法输出、网页表单/异步路径和存储语义，也覆盖缓存失效、磁盘索引复用、并发模型加载、连接恢复、JSON 原子写入和旧记录迁移。不依赖真实模型，不代表已验证真实推理效果。

另以相同的 70 条消息和 32 个查询直接对照 main `f4b7495`：分词、索引统计、全部结果顺序及默认前三条一致。隔离浏览器覆盖第 4 个登记模型、批量检测、历史、人工校验和移动布局；便携入口在中文／空格目录及其他工作目录真实启动，未调用模型、未创建 SQLite 文件。

效果评估应独立比较各单模型与投票版本的风险标注一致性、明确结论覆盖率和耗时。真假数据集标签不应直接当作语言风险等级标签。
