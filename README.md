# FakeNgin

消息风险分析平台。本分支 `feat/risk-voting` 参考 main 的可用模型展示逻辑（`8dda39f`），提供自动风险等级投票、逐模型进度、网页批量检测、可导出的历史报告和人工校验。

## 安装与运行

建议使用 Python 3.10 或更新版本，并在虚拟环境安装依赖：

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

只查看界面与已有报告不需要下载模型，安装网页依赖后启动：

```bash
python -m flask --app src/app.py run --host 127.0.0.1 --port 5000 --no-debugger
```

网页使用已就绪的本地检测服务，不提供云端 API 设置和调用入口，也不会读取服务器密钥进行推理。检测页和数据页只展示实际可用的风险模型，以“分析模型 1、2……”标识；没有可用模型时显示空状态。真实模型标识仍保留在历史数据和结构化导出中，用于追溯。

如需本地推理，可另行安装并启动 [Ollama](https://ollama.com/)，准备项目已登记的本地模型。网站和启动器不会自动安装服务或下载权重：

```bash
pip install ollama
```

网站位于 http://127.0.0.1:5000/ ，风险检测位于 http://127.0.0.1:5000/detect 。
没有模型也可以打开页面、维护数据和查看已有报告。模型服务在网站启动后才就绪时，请重启网站以刷新可用模型列表。

风险检测、检测历史和数据浏览均无需登录；人工校验需要账户登录。风险检测结果不写入真假标签，人工校验负责维护消息标签。

## 人工校验

导航中的“人工校验”进入 `/verify`，登录后可浏览全部消息、添加、修改或删除消息，也可逐条标注“真实／虚假／中立”，跳过消息或重置跳过列表。每页 20 条，修改时核对文件、行号和内容指纹，拒绝过期表单。

人工标签写入原 CSV，完整模型报告仍保存在历史记录中。修改正文会清除该行过时的机器风险字段，已保存的历史报告保留原文和原判断；人工表单不覆盖机器风险字段。数据页继续负责导入与批量检测，历史页继续负责保存每次检测成果。

## 风险投票

网页从项目已登记的本地风险模型中列出当前可用成员，不预先展示三个固定席位。有一个模型时默认单模型，有两个或三个模型时默认投票。各模型使用相同的风险定义，独立分析来源描述、证据表述、绝对化断言、恐慌煽动、强迫转发等文本特征。通知、科普、引用专家或情绪表达本身不构成高风险依据。

风险分为 0–100 分，不是真假概率。高风险不等于虚假，低风险也不保证真实。输入缺少上下文时，模型可以返回 `risk_score: null` 表示无法评分；这与请求失败分别展示。

初始等级界线（尚未经过数据集校准）：

| 风险分 | 等级 |
| --- | --- |
| 0 ≤ 分数 < 40 | 低风险 |
| 40 ≤ 分数 < 70 | 中风险 |
| 70 ≤ 分数 ≤ 100 | 高风险 |

- **单模型**：选择一个模型，显示它的风险分、等级、理由和耗时。
- **投票**：选择两个或三个模型，每个模型一票，按风险等级等权计票。不做模型相似性加权。
- 多数门槛为 `floor(选定模型数 / 2) + 1`：两模型必须同意，三模型中至少两票同等级。
- 失败、缺失与弃权不会降低多数门槛。没有多数票或有效票不足时，改用成功返回的风险分的**算术平均值**，再按同样的 40、70 界线分档。分类使用未四舍五入的均值。
- 页面明确标记“多数投票”或“平均分兜底”。如果只有一个模型成功，均值就是该模型分数，并提示仅有一个有效结果；只有零个有效分数时才无法判断。
- 失败、缺失、弃权均不计入平均分，也不按 0 分计算。均值是风险评分，不是真假概率。
- 页面展示选定数、有效结果数、各等级票数及全部成员状态；“2/3 支持”只是投票比例。
- RoBERTa 学习真假标签，不参与本次风险投票；固定 50 分的模板模型默认禁用且不在投票白名单中。

示例：80/90/10 → 高风险（多数票 2/3，优先于均值）；10/50/90 → 中风险（均值 50）；90/10 → 中风险（均值 50）；90/失败/弃权 → 高风险（均值 90，只有 1/3 有效）；全部失败或弃权 → 无法判断。

模型顺序执行，避免同时加载多个本地大模型。网页通过 `/detect/stream` 的 NDJSON 响应实时展示每个模型的等待、分析、完成、失败和弃权状态，分数与理由在各模型返回时立即显示。进度条表示已返回的模型数量，不估算单个模型内部的完成百分比。最终报告显示等级票数、逐模型分数条，以及均值兜底时的计算过程。

单条工作台的推理在当前请求中运行。刷新或关闭单条检测页面不会恢复此前的进度；服务器发现连接关闭后停止推进后续模型，正在执行的单次调用可能要等到返回或超时。中断的部分结果不生成完整报告。多模型用时取决于设备、模型加载及重试；Ollama 有独立超时和最多两次请求尝试，主动弃权不重试。无 JavaScript 时仍可提交普通表单获取最终报告。数据页的批量检测使用下述持久化后台任务。

提示词版本为 `risk-v1`，返回字段为 `risk_score` / `reason`；客户端拒绝 NaN、越界、旧 `probability` 字段和无有效理由的响应。本地模型使用 JSON Schema，各适配器保留自己的采样和消息格式配置。命令行云端适配器保留供非网页调用；网页明确拒绝云端来源，旧云端批量任务不能继续执行。

## 检测历史与报告

每次完成的网页检测自动保存到 `database/risk_reports.sqlite3`，包含消息原文、实际模型标识、逐模型分数/状态/理由/耗时、最终等级、聚合方式、有效数量、提示词版本和完成时间。页面使用通用模型名称，结构化导出保留追溯信息。全部模型失败的完整检测也保留，输入验证失败和中途断开的检测不保存。保存失败时页面仍展示当前结果并说明失败，不显示已保存入口。

- `/history`：按时间倒序浏览，每页 20 条，支持按原文关键词搜索。
- `/history/<id>`：查看原文和完整历史报告，使用保存时的结果，不重新调用模型。
- 结果工具栏支持复制完整文本报告，下载 TXT、JSON、CSV；CSV 每个模型一行，使用 UTF-8 BOM 并防止文本被表格软件当成公式执行。
- 页面时间按浏览器时区显示；导出保留 UTC 时间和原始分数精度。

SQLite 使用 Python 标准库，无需额外数据库服务。同一本地实例共享历史记录，重启后仍可读取；数据库已被 Git 忽略，不会提交原文与报告。网站不会自动安装或下载模型。

## 数据准备与网页批量检测

两个页面分别负责实验输入和检测成果：

- `/data`：导入、搜索和选择消息样本，配置模型并启动批量检测；仅显示最新检测状态和报告入口。
- `/history`：保存每一次完整检测的原文、逐模型评分、理由、聚合过程和可导出的报告。同一样本再次检测会产生新报告，保留先前结果。

数据集初始可以为空，不影响单条云端检测。数据页支持上传 UTF-8 CSV（可带 BOM，必需列为 `content`、`内容` 或 `正文`，`source`/`来源` 可选），或粘贴多行文本（每行一条）。每次导入最多 500 条、1 MiB，每条不超过 6000 字符。导入只保存样本，不调用模型；每次写入新的 CSV，不覆盖现有数据。

导入后勾选消息或全选本页，选择单模型或多模型投票，以及 DeepSeek 云端/本地来源，再点击“开始批量检测”。启用 JavaScript 时选择会在当前浏览器标签页中跨页保留，支持分多页选取样本；清空选择可一次取消全部。每批最多 100 条，后台逐条、逐模型顺序运行；每条完整结果立即保存到历史。单条失败会继续处理后续消息，全部模型无法评分的完整报告也会保存。页面可查看每条状态、当前消息的逐模型进度，并从报告入口查看完整成果。

批任务写入 `database/risk_batches.sqlite3`，刷新或重新打开 `/data?job=<id>` 可继续查看。取消在当前模型返回后生效，后续模型与消息不再执行；尚未完整的消息不生成报告，已经保存的报告保留。服务器重启会把未结束任务标为中断，不自动重跑；需要继续时，选择未完成的样本重新提交。普通表单也能导入和创建任务，无脚本时可手动刷新查看进度。

任务保存选定消息的内容快照、文件/行号/指纹和模型配置，拒绝重复或已变化的行引用。检测报告关联样本但不修改其原文或数据集标签。报告显示所属批次，JSON/CSV 导出保留批次及样本引用（索引为 0 起始），网页和文本报告序号从 1 开始。

## 批量评分与旧数据

```bash
python src/newscheck.py
```

批处理根据 `model.score_kind` 分开存储：

- 风险模型 → `risk_score`、`risk_model`、`risk_reason`、`risk_prompt_version`。
- 原有真假分类器 → `fake_probability`。

旧 CSV 读取时为新字段补空值，写回时增加列；原来的分数和标签不会自动转换为风险分。修改来源等元信息时保留已有风险字段，修改正文时清除旧风险结果以便重新评分。网页数据页主要用于准备和选择样本，完整检测结果在历史记录里查看。

网页报告与旧 CSV 分开保存。CLI 仍是单模型批处理，每 20 个成功结果保存一次，单条失败继续；强制中止时最近未保存的结果可能需要重跑。

## 可选的 RoBERTa 训练

RoBERTa 保留为独立的真假分类实验，未参与风险页面。

```bash
pip install torch transformers
python src/train_rumor_model.py
```

训练数据为 `database/newsdata/output/` 下 CSV，`nature=True` 表示谣言，`False` 表示非谣言；权重输出到 `models/rumor-roberta/`。首次运行下载基座模型，脚本默认通过 `hf-mirror.com`，可使用 `HF_ENDPOINT` 覆盖。仓库不包含训练权重或真实模型评测结论。

## 测试

```bash
python -m unittest discover -s tests -v
```

测试使用模拟模型和隔离的临时数据，覆盖多数票、分歧、失败、弃权、边界、非法输出、逐模型事件时序、断流、历史持久化/检索/导出、导入与引用校验、批任务取消和中断恢复、人工校验登录与完整操作流程，以及动态模型名单和禁止网页云端调用。不依赖真实模型，不代表已验证真实推理效果。

效果评估应独立比较各单模型与投票版本的风险标注一致性、明确结论覆盖率和耗时。真假数据集标签不应直接当作语言风险等级标签。
